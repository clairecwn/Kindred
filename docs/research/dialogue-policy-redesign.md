# Journal conversation policy, October 2026

The regression case is `src/lib/analysis/__tests__/fixtures/write-journal-entry.json`, copied from the user-requested “Write Journal Entry” test chat. The assistant first invented a mechanism for nap grogginess, then repeated an unsupported interpretation, then chose fries over the user's fatigue, nap guilt, and waiting readings. A reply that merely restates what it understood also left no easy next turn.

## Research applied

- [AHRQ's OARS guide](https://www.ahrq.gov/evidencenow/tools/oars-model.html) describes open questions, affirmations, reflections, and summaries as complementary communication skills. Kindred uses those as *dialogue acts*, not clinical scripts. Validation comes before an interpretation; an open response offers one easy next move.
- [Research on focusing in motivational interviewing](https://pmc.ncbi.nlm.nih.gov/articles/PMC7610531/) found that focus can be created or shifted through questions, listening statements, information, or meta statements. Kindred therefore chooses a `SHIFT` act with a takeaway and a bridge, not an unexplained new question. The app is a companion, not a therapist; these are communication patterns, not a claim of treatment.
- [Research on conversational follow-up questions](https://aclanthology.org/2020.acl-main.90/) supports checking whether a question follows the current exchange or changes topic. The question/answer bank and repetition check remain part of the response validator.
- [Groq's rate-limit documentation](https://console.groq.com/docs/rate-limits) describes 429 and `retry-after`; [Groq's production guidance](https://console.groq.com/docs/production-readiness/security-onboarding) recommends exponential backoff for 429 and 5xx. The transport now uses bounded retries, timeouts, model fallback, and optional Gemini fallback. [Gemini documents its own rate limits](https://ai.google.dev/gemini-api/docs/rate-limits) and [generateContent API](https://ai.google.dev/api/generate-content).

## Implemented policy

The semantic pass extracts grounded topics, evidence, coverage, affect, and incidental status. It no longer writes the reply. `dialogue-policy.js` updates bounded per-topic variables after every user turn: salience, emotional intensity, exploration depth, unresolvedness, engagement, new information, and closure readiness. A weighted score ranks topics and a softmax reports relative priority. These weights are heuristics, **not calibrated probabilities or a diagnosis**. Current user redirection can override ranking; slight rank changes do not jerk the focus around. Explicit links can keep two meaningful concerns together. Incidental details get a penalty.

The policy chooses `VALIDATE`, `REFLECT`, `EXPLORE`, `DEEPEN`, `SHIFT`, `SUMMARISE`, or `SOFT_CLOSE`. `SOFT_CLOSE` enters `LANDING`, not an ended conversation. New meaning reopens it. The separate writer receives an action contract and the user's recent voice profile; the validator rejects known posh/unsupported expressions, task probing, repeated questions, and replies that miss the planned conversational function.

The policy deliberately does not force a question on every turn. A reflection needs a specific contribution a user can correct or add to; a landing offers a low-pressure way to save and leave. A new reply after landing is processed normally.

## Follow-up from the assignment avoidance transcript

The second regression fixture is `src/lib/analysis/__tests__/fixtures/assignment-avoidance.json`. It captures a repeated “which part?” probe after the user has answered “the whole thing,” “everything,” and “all the topics,” plus unrelated callbacks to the egg incident and a drift into formal English. Those are failures of turn tracking, focus, and voice continuity, not just a weak sentence template.

[Motivational interviewing process research](https://pmc.ncbi.nlm.nih.gov/articles/PMC6250061/) ties helper utterances to subsequent client responses; repeated narrowing without using the answer works against that conversational sequence. [Focusing research](https://pmc.ncbi.nlm.nih.gov/articles/PMC7610531/) and [research on summaries in motivational interviewing](https://pmc.ncbi.nlm.nih.gov/articles/PMC3202953/) support a short reflection or summary before a genuine change of focus. [A dialogue style-alignment study](https://aclanthology.org/2025.sigdial-1.16/) found that current language models do not consistently match human style, so explicit voice guidance and output checks are warranted. We borrow communication patterns here, not clinical treatment rules.

The turn model now computes question pressure from the assistant's recent narrowing questions and the user's broad answers. A broad answer is treated as an answer: the policy lowers task-content priority, chooses a reflection about the pressure or avoidance, and the critic rejects another subpart question. Recency and a topic facet separate task details from the user's experience and help keep incidental journal incidents out of a focused chat. An explicit user redirect can still shift focus; `SHIFT` requires a brief landing and bridge. The voice profile uses the journal as a prior and weights short recent replies lightly, so “everything” does not erase the user's established register. These scores are engineering heuristics that need broader, blinded evaluation; they are not probabilities of a user's inner state.

## Reliability and remaining limits

The model transport retries transient 408/429/5xx, network errors, and empty completions with bounded backoff and a 20-second timeout. It fails over immediately on daily quota exhaustion, with Qwen as the writing backup and GPT-OSS 20B as a last resort; assessment tries the smaller model before Qwen to preserve its short-term output quota for replies. A configured Gemini key adds another route. The UI persists a user message under one turn ID, shows a pending assistant state, and retries that same turn without adding another user bubble. A failed turn is never displayed as an assistant echo. Remote APIs may still process a timed-out request; local turn IDs prevent duplicate chat bubbles, not duplicate provider billing.

A live replay hit an actual `openai/gpt-oss-120b` daily token limit and, later, Qwen's per-minute output quota. The initial implementation retried the exhausted model and eventually returned an irrelevant fries reply when semantic assessment failed. After the fallback and policy repairs, the same turn produced a question-free `SOFT_CLOSE` focused on fatigue and nap grogginess. That replay establishes a narrow regression improvement; it does not prove all conversations will land well.

`VITE_*` keys are visible in client bundles. This remains a local testing arrangement; production release requires a server-side proxy before any journal text or keys are sent from a public deployment.

An initial opt-in replay (`npm run eval:journal-models`) compared Groq-hosted `openai/gpt-oss-120b` with `qwen/qwen3.8-27b` on three turns from the fixture. Both avoided the fries topic. Qwen was more concise in this tiny sample; GPT-OSS mirrored lowercase more but added long dashes, canned reassurance, and an unsolicited task step on the `hais` turn. Both asked about nap length after the user raised nap guilt and grogginess, which misses the stronger concern. These are qualitative observations from **three turns**, not a provider ranking. Gemini was not configured, so no Gemini comparison ran. The default model remains unchanged. Before switching, blind-rate focus, factual grounding, validation, continuation, register match, latency, and failure rate on a wider set of entries and multiple samples per condition.
