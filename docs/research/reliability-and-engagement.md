# Companion reliability and engagement, October 2026

The `shower-misread.json` regression records a common failure sequence: a final routine action stole focus from study pressure; a literal short answer was over-interpreted; explicit pushback and two minimal acknowledgements were treated as invitations to keep explaining. The same chat flow could show “unavailable” because an assessment, writer, or revision model call failed or a hard response check rejected the final draft.

## Research used

- [Groq rate-limit guidance](https://console.groq.com/docs/rate-limits) distinguishes daily and minute limits, reports HTTP 429, and supplies `retry-after`. Repeating the same model immediately after 429 spends time without improving the chance of a response. The transport now cools down that route and tries another configured route promptly.
- [Groq deprecation guidance](https://console.groq.com/docs/deprecations) distinguishes preview and production models. The writer still prefers the configured primary production model; the assessor uses the smaller production model by default. A preview model remains a fallback, not the single route.
- [A sequential analysis of motivational interviewing skills and client responses](https://pmc.ncbi.nlm.nih.gov/articles/PMC6250061/) and [work on conversational discord](https://pmc.ncbi.nlm.nih.gov/articles/PMC10661888/) support treating user reactions as feedback about the interaction. Kindred is a companion, not therapy; the borrowed pattern is to back off an interpretation when the person resists it.
- [Language Style Matching in Large Language Models](https://aclanthology.org/2025.sigdial-1.50/) studies adaptation to a conversation partner's language style. Kindred keeps the user's long journal and historical style as a prior when a few short replies carry little style information.

## Implemented behavior

The engagement signal separates a terse literal answer to an abstract question, explicit pushback, and repeated bare acknowledgements. The policy selects `REPAIR` for the first two. A repeated bare acknowledgement can lead to a soft close only after checking for meaningful unvisited concerns. On `REPAIR`, an incidental previous focus loses priority to a meaningful unresolved concern; the writer is told that prior assistant interpretations are not facts. It cannot invent physical sensations absent from user evidence. A single brief reply alone is not treated as disengagement.

The model transport fails over immediately on 429, carries cooldown timing to the UI, and validates JSON before treating it as a successful assessment. Routine short-turn repair/landing uses the stored debrief state without another assessment call. The UI retries a failed opening or saved chat turn automatically for bounded transient failures; the same user turn ID is kept. A final failure distinguishes rate limits from missing configuration. Quality checks reject unsupported, off-focus, or conspicuously formal replies.

The assessor, writer, and reviewer now receive bounded recent turns and question-answer pairs. Long journal context retains sections from the beginning, middle, and end so a later paragraph does not erase an earlier concern. This reduces overlapping input and response latency without treating older assistant guesses as user evidence.

These are heuristic policies, not calibrated probabilities of user interest. The tests cover policy actions, style continuity, an assessor-free repair turn with a mocked model, rate-limit behavior, and retry caps. Live provider reliability still depends on credentials, quotas, and provider availability.

## October follow-up

The group-project transcript exposed an output-boundary bug: the writer saw private dialogue labels and returned `**shift**` and `**landing**` as chat text. The final validator now rejects private labels, unmatched emoji, stiff stock phrasing, and unsolicited process advice. The writer receives the instruction without the private action/phase keys. Casual voice checks are stricter, and the saved writing style contributes a weak prior only when the new entry is too short to establish its own style.

Debrief coverage now checks meaningful unvisited topics before a brief acknowledgement causes a soft close. The selected next thread is the strongest grounded remaining concern, not a predetermined journal detail. A terse reply can bridge without demanding another question. This follows [dialogue-state tracking research](https://aclanthology.org/2022.sigdial-1.33/) and the [motivational interviewing literature on premature advice](https://pmc.ncbi.nlm.nih.gov/articles/PMC3330017/) as design guidance; the weights are still uncalibrated heuristics.

A synthetic Groq request on 8 October returned HTTP 200 with requests and tokens remaining. At a deliberately tiny output cap it returned `finish_reason: length` with no visible content; a structured-output request at a practical cap succeeded. End-to-end synthetic journal runs then showed a separate problem: the writer's task-breakdown question could fail quality checks and surface as “unavailable.” One revision also failed a style check. Later runs hit 429 on the 120b route while 20b and Qwen still answered. Thus the observed failures were not one universal connection issue or one universal quota issue. The assessor output cap was raised; malformed or empty completions fail over promptly; capacity errors are classified separately; each model call has a total time budget; a rejected task probe makes a question optional during revision; and a missing question alone can no longer discard an otherwise valid reply. No private journal transcript was used in these live checks. [Groq's error reference](https://console.groq.com/docs/errors) distinguishes 422, 429, 498, and server errors.

## Continuation follow-up

A later short-answer test exposed a dialogue-action ambiguity: the assessor's `answer` label was treated as a reason to prohibit follow-up even when the user was answering Kindred's question. Only an actual question from the user now activates that direct-answer behavior. The debrief state also discounts model-claimed topic coverage unless there is a substantive user chat turn, and it can bridge to a comparable unresolved thread after the user answers a companion question. This preserves gentle endings after repeated acknowledgements without treating all brief answers as endings. An optional focused model pass supplies a concrete continuation when an otherwise valid response would stop too early.

The saved profile was already rebuilt from prior user-authored entries and chats and sent to the writer. In the reported style failure, the current journal itself strongly signaled a casual voice, so missing memory was not the main cause. The writer's formal instructions and fallback model route weakened those cues. The casual voice instruction is now explicit at the top of the writer prompt; formulaic comfort phrasing is rejected; and the production 20b model precedes the Qwen preview fallback when 120b is unavailable.
